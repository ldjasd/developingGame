# 呈现框架重构蓝图（FRAMEWORK_REBUILD）

> 2026-11-03 立项。用户定调：现有呈现框架（DOM 文档流长页面＋卡片＋弹窗的网页骨架）是错误地基，在它上面修补修不好——与图标「烘焙扁平图反复挖补」同一教训（图标最终靠分层重构解决）。本蓝图只换**呈现层**：游戏系统、数值、剧情、存档结构、战斗逻辑全部保留不动，老存档必须可读。
> 依据：GAME_AUDIT.md（22 条，主线结论「系统层是完整的游戏机、呈现层还是网页」）、PLAYTEST_WEEK1.md（24 条）。

## 一、新框架规格

### 1. 固定视口舞台壳（Stage Shell）
- `html/body` 锁定 `100dvh`、`overflow: hidden`，**文档永不滚动**；`.wrap` 由文档容器改为 `position: fixed; inset: 0` 的纵向 flex 舞台：HUD（flex none）→ 场景区（flex 1、min-height 0）→ 底部导航坞（flex none）。
- 每个场景视图是舞台区内的一块**全屏构图面**：管理类场景在面内自滚动（`overflow-y: auto`、内容列居中限宽 1060），舞台类场景（标题/战斗）`overflow: hidden` 一屏到底。
- 壳的任何祖先不加 `transform/filter`，保证 body 级 fixed 弹窗/toast 定位语义不变（现有弹窗体系可直接沿用）。

### 2. 场景管理器（Scene Manager）
- 沿用现有 `showScene(name)` 作为唯一切换入口（10 场景：title/daily/train/shop/status/match/gallery/saves/settings/battle），语义不变：`body[data-view]` 驱动壳级显隐（战斗/标题时 HUD 与导航坞退场）。
- 切换过渡：保留并收敛现有 `.view-in` 淡入滑入（0.38s，`prefers-reduced-motion` 与设置「减少动效」时关闭）；场景背景层 `.scene-bg` 交叉淡化沿用。
- 场景 = 全屏舞台构图：每屏有明确的「主视觉区＋操作区」构图（见第三节逐屏目标），不再是卡片自上而下堆叠的文档流。

### 3. HUD 覆盖层
- 旧顶栏大卡（359px）瘦身为**单行细条 HUD**：半透明面板＋毛玻璃、圆角悬浮（与舞台留边距），只常驻核心信息（日期/AP/金钱/体力＋状态·存档·说明入口）；次要信息（伤病/名声/影响力/排名/心态）桌面常驻、窄屏（≤900px）收起（状态屏可查）。
- 场景导航由文档流 pill 行改为**底部导航坞**：胶囊条、毛玻璃、横向可滚，浮在舞台底部；战斗/标题场景自动隐藏（既有规则）。
- 调试入口已于第一批整改下架（测试档/TKO死战/恢复按钮出货界面不可见、函数保留），本框架不再回加。

### 4. 对话框/确认框：舞台内游戏式组件
- 既有弹窗（modal-mask 体系）定位与行为不变，但视觉口径定为「舞台内组件」：居中卡＋深色遮罩＋代表色描边，后续场景迁移时逐个把 `confirm()` 式文字墙弹窗改为图文并茂的游戏式面板（对手卡、奖励结算卡等）。
- 战斗新增两类舞台内组件（本期样板）：**开战准备层**（全屏覆盖：双方对位卡＋规则一句话＋开始按钮，点了才开战）与**实况日志抽屉**（右侧滑入，默认收起，不再占版面）。

### 5. 战斗舞台规格（样板场景）
- 纵向 flex 一屏构图：顶部对位条（回合横幅居中浮签＋双 HP 大条卡，HP 条加高、体力细条、重创槽并列且标计数）→ **擂台 flex 1 全幅**（场景图铺满 cover）→ 状态 pill 瘦行（横滚、含「实况」抽屉按钮）→ 指令区钉底（手动＝触屏摇杆/桌面提示，自动＝战术＋指令按钮组，矮屏压缩描述行）。
- 立绘：姿势图与对手图**程序化去底**（米色底 flood-fill 抠除＋羽化，透明 WebP），贴擂台地面（接地椭圆影）、尺寸按擂台容器相对单位（cqw/cqh）定标、目标高度约占擂台 65–75%（竖屏受双人并排宽度约束取可达上限），随舞台尺寸自适应；VS 横幅/回合横幅/KO/击倒演出沿用既有实现并保证在舞台内可见。
- 重创规则在**开战准备态**一句话讲明（槽满 100 K.O.、单发 ≥ 当前 HP 30% 直接 K.O.、25–30% 击倒读秒），不再只埋战斗页小字。
