# Godot 桌面正式版（2D 骨骼）提案与实施记录

## 1. 一句话提案

正式版从网页版迁移到 **Godot 4 桌面版**：人物保持 2D、用引擎原生骨骼动画（Skeleton2D+Bone2D+蒙皮网格），系统与数值以网页版 v43 为准整体移植，最终交付 Windows 可玩包；网页版降为原型/参考实现。

## 2. 背景与来源

- 2026-11-17 用户拍板：正式版＝Godot 桌面版，人物保持 2D、用骨骼动画；**彻底弃用「立绘→AI 视频→逐帧抠图」管线**；3D 建模路线不走；网页版（SW v43）降为原型/参考实现，系统数值以它为准。用户设备更正：有自己的 Windows PC。
- 弃抠帧管线的原因（结构性缺陷，非单次事故）：拳套出框被裁、去底矩形/残片残留、发梢被吃、倒地帧塞竖格读不出平躺——每批都要逐帧返修，管线本身不稳。
- 用户追加（同日）：「先做建模吧，之前的都是碎的人物」；随后改为整体交付——「你就正经把移植做好，我先不确认半成品了」。据此取消半成品确认停点，里程碑改内部 QA 节点；人物不碎是助手内部自审红线，验过才算完成；只有用户能定的设计抉择/素材硬缺口记入本文待拍板清单，不停工。

## 5. 骨骼动画管线（已落地，含实测教训）

**结构**：`scripts/fighter_rig.gd`（FighterRig）——11 骨链（Root→Spine→Head、双臂 UpperArm→ForeArm、双腿 Thigh→Shin）；动画全部由引擎内骨骼关键帧在代码中生成（ANIM_DEFS：idle/straight/jab/hook/upper/body/block/hit/dodge/victory），不使用任何抠帧素材。`scripts/rig_factory.gd` 按 `data/rig_params.json` 建任意角色。

**部件切分**（对齐 modular-character-rig.md 的模块思想，落到单图切分）：头/躯干/上臂×2/前臂＋拳套×2/大腿×2/小腿＋鞋×2 共 10 部件，区域多边形按解剖手绘、刻意重叠、边缘 9px 羽化；部件专属「排除区」挖掉捎带到的他人像素（如前臂区里的下巴/刘海，由下层头部部件兜底）。

**实测教训（已固化进代码注释）**：
1. **全零权重＝扇形撕裂**：渲染器只取每顶点权重最大的 4 根骨并归一化；权重全零的顶点被塌缩到原点，拖拽相邻三角形成扇形。主角初版 112/575 顶点全零（发梢/裙摆缘超出所有骨骼半径）。纪律：任何顶点权重和恒为 1，超出覆盖兜底归最近骨骼。
2. **单图距离权重交叉污染**：抱架姿势拳套贴脸、双臂交叠，脸像素混进前臂权重→出拳时脸被拖糊。故改部件隔离（见上）。
3. **改 `Polygon2D.bones` 后必须 `queue_redraw()` 并等帧**，否则截到的还是旧帧——调试实验曾因此全灭，排障时先怀疑自己的实验台。
4. **对手推广**：侧面图纯色背景色键抠图（`tools/prep_opponents.py`）；关节点逐人看网格图手放；部件多边形按「最近关节锚定＋本地骨长比例」从主角模板映射＋绕质心外扩补重叠；朝右的角色整图＋关节点一起镜像（偏移方向在镜像帧里不变，**不要再对偏移取反**——实测翻车过）；每人有动画旋转缩放（0.8~0.9，高站姿角色幅度收一点）。

**主角 rig 资产复用核查结论**：web 的 `assets/rig/me/` 8 件 WebP 部件是从 3/4 视角定稿图切件、分辨率偏低、视角不合侧面骨骼——**不复用**；改用主角侧身抱架定稿图 `web/assets/pose/guard.webp`（700×1004、真 alpha）整图切部件，已验证为正式管线。对手同理用各自比赛服侧身图（pose_src_batch/pilot，共 7 人）。

**验收标准**：抱架/直拳峰值/直拳中间帧/受击截图逐张自审——关节不分离/不撕裂、整体读作一个完整的人；引擎直录视频验连贯性。主角已过线（截图与视频存 `research/godot_rig/`）；7 名对手抱架已逐人验过（完整），出拳幅度/个别部件仍有已知瑕疵（见 §7）。

## 6.5 实时战斗改造方案（2026-11-21 用户拍板）

**决策**：Godot 战斗由回合制交换改为**实时操作**（用户 2026-11-21 试玩回合制后拍板；参考作 Love Upper 为实时，网页版即实时实现）。**KO 判定规则不变**——现行体系（重创积累跨 25/50/75 击倒、满格 KO、单回合 3 击倒 TKO、点数判定、减伤封顶 70%）原样保留；用户侧试玩报告的 KO 塌缩（20 场 18 KO、点数仅 1 场）定性为**回合制适配标定问题**，靠实时版标定解决（见下「标定计划」），不动判定规则与用户硬数字。

**实现前提**：先从仓库同步——远端 HEAD 已进至 8f826f35（含用户侧试玩修复：正式赛改回每周第 7 天 1 场、心态系统按 web 口径补回、8 个合成音效、`dev/playtest.gd`、弹窗/血条/战报修复），我方本地 godot 树落后于仓库；战斗改造开工前先拉齐并跑一遍现有冒烟基线，避免覆盖用户侧修复。

### 目标体验

- 玩家自己走位、自己出拳、抓闪避反击窗口——对齐 web 手动模式与 Love Upper 的实时手感；回合结构不变：3 回合 × 45 秒真时，回合间休息（手动模式可等满 60 秒或跳过，并选下回合战术 强攻/均衡/稳守）。
- 三模式保留且共用同一套判定内核：手动（实时操作）／自动观看（AI 代打，玩家用战术＋指令干预）／模拟跳过（解析模型快速结算）。

### 从 web 提炼的实时模型（移植基准，源：`web/js/battle.js`、`game.js`、`data.js`）

连续时间推进：相位机 fight／break／down／over；重创衰减、指令 CD/buff、反击/破防窗口全部按**秒**连续递减（Godot 侧 `_physics_process` 60Hz、dt 秒制；web 手动 tick 为 50ms、自动 tick 为 0.5s 游戏秒，数值已按秒归一）。

**手动模式（玩家）**：
- 移动：横向速度 26 单位/s ×（0.7＋步伐×0.03）、纵向 34 单位/s；格挡中不能移动；与对手最小间距 6；体力回复：移动中 3.5/s、静止 7/s、格挡中不回。
- 出拳表（MPUNCH，左右手变体；coef 即用户硬数字拳种系数）：刺拳 coef 0.6／射程 20／体力 2／CD 200ms；直拳 1.2／20／4／340ms；摆拳 1.4／16／6／520ms（右手 1.42／530ms）；上勾 1.3／15／6／500ms（右手 1.32／510ms）；击腹 0.8／16／4／380ms（右手 0.82／390ms）。左右手差 +0.02 是 web 的呈现变体，Godot 侧并回 5 个拳种键、CD 取左右均值。出拳 CD 缩放 ×clamp(1.3 − 出拳速度×0.032, 0.45, 1.2)；体力 <30 时 CD ×1.4、伤害 ×0.75。
- 距离带（射程判定，超距＝空挥：断连击、不涨熟练度、给对手开反击窗口）：>20 全拳种够不着；16~20 仅刺/直；13~16 摆/击腹可达（上勾 15）；≤13 全可达。对手侧同规则降级：摆/上勾在距离 >13 自动改直拳、击腹 >16 改刺拳。
- 格挡：按住生效——被格挡伤害 ×0.3、重创只积一半、格挡方体力 −3；破防期间（被击腹穿透后 1.5s）格挡失效且吃直拳 +20%。对手抱架概率 calcBlockChance＝0.16＋稳守战术 0.08＋防守反击型风格加成，钳制 0.05~0.45；铁壁期间必抱架。
- 闪避：方向闪避，成本 15 体力，无敌帧 300ms，CD 1500ms；闪避成功（或对手拳落空）开 **1 秒反击窗口**：方向对应拳种（后闪→直拳／下闪→上勾／侧闪→摆拳）**+40%**、其余拳种 **+30%**，窗口用掉即关。
- 垫步 dash：双击方向键，位移 13 单位，成本 6 体力。
- 命中公式 calcHitChance（自动/手动共用）：0.70＋（精准 − 对手步伐）×0.01，钳 0.30~0.95；战术三角乘子：守方稳守时攻方打点 ×0.88／其余 ×0.7，守方打点时攻方强攻 ×1.06／其余 ×0.95，攻方强攻 ×1.02，乘后二次钳制。
- 伤害公式（dealDamage，逐项照 web）：raw＝力量 × 拳种系数 ×（1＋熟练度×0.05）× rnd(0.9, 1.1) × 倍率组（强攻战术 ×1.3、暴击 10% 概率 ×1.5、组合拳 buff ×(1＋0.5×(0.7＋技术×0.03))、场边训话 ×1.1、回合战术 ±10%、死战 ×1.1、侦察弱点 ×1.3、对手风格 dmgMul）；净伤＝max(1, raw − min(防守×1.0, raw×0.7))（**减伤封顶 raw 的 70%**）；格挡 ×0.3、击腹穿透格挡 ×0.7 并破防、打点守方卸力 ×0.9、连击加成在净伤后乘（见硬数字清单）。
- HP 池：hpMax ＝ 100 ＋ 耐久×14（我方再 −伤病×0.5、下限 50）——**换回 web 原值**，替换回合制适配池（140＋耐久×2.2）。
- 体力（上限 100）：出拳按拳种 stam 扣，倍率叠加——战术 强攻 ×1.5／打点 ×0.7、组合拳 buff 期 ×2.6、对手风格 stamMul、心态疲劳 ×1.1、战靴 gearStamMul；命中削守方体力 −1/拳、击腹再 −净伤×0.6；回合间双方各 +30。

**对手 AI 节律（自动模式双方共用 tryAttack 概率节律；手动模式对手走 foeTickManual 骨架）**：
- 自动节律：每 0.5 游戏秒掷一次出拳概率 p＝0.24＋出拳速度×0.012；对手 ×1.15×风格 freqMul；稳守战术 ×0.6；铁壁 buff 期 ×0.40；体力 <30 ×0.7；体力 <6 强制喘气（+4.6/0.5s）；未出拳则回气 +0.92/0.5s。
- 选拳 pickPunch：权重＝1＋熟练度×（我方 1.6／对手 1.0），叠风格权重（按 styleIntensity 插值）与战术倾向（强攻：摆/上勾 ×1.35、刺 ×0.8；打点：刺 ×1.5、直 ×1.25、重拳 ×0.75；稳守：直 ×1.15 等，逐项照 web tacBias 表）。
- 手动模式对手：目标距离按战术/风格（强攻 11、力量型 11、稳守 14、速度型 14、防反型 15、打点 16），每 0.4~1.0s 重掷移动方向，移速 22 单位/s ×（0.7＋步伐×0.03）×风格 moveMul；出拳间隔 max(0.33, (rnd 0.55~1.0 − 周数×0.03)×0.87) 秒，稳守 ×1.5、÷freqMul，铁壁期计时 ×0.40，反击窗口内抢出 ≤0.45s；距离 ≤19 且体力 ≥6 才出拳；自身回气 3.5/s。玩家格挡时，对手有概率改打击腹破防（力量/防反型 0.35、其余 0.18）。
- 指令 AI（foeCommandAI，每 tick 至多一条，优先级 铁壁＞搂抱＞组合拳，陪练不用）：铁壁——第 2 回合起 HP＜人格血线（0.28/0.35/0.42）或己方重创 ≥72；搂抱——人格愿意抱且（体力 <22／玩家连击 ≥4 且体力 <65／重创 ≥78 且 R2 起）；组合拳——press（体力 >70 且开场 8s 后）／burst（己方连击 ≥3 或玩家重创 ≥60）／closer（末回合或 R2 起点数领先），按人格 comboWhen 分型。
- 回合间变招（endBreak 人格评估，照 web）：点差 ≥20 触发 comeback 转强攻／protect 转稳守，残血 <35% 触发 desperate 转强攻，不满足回 base 战术（G7 定版门槛 ±20）。
- 指令系统（双方同规则、同 CD 同效果）：组合拳 buff 10s（期间连击被格挡不清零、伤害按上式 buff 倍率）；铁壁 10s（必抱架＋重创积累免疫＋自身出拳频率 ×0.40）；搂抱（缠抱停战 1.2s 双方停手回气、使用者回体按需求 12/6/3、对方 +8、双方连击清零、同场第 4 次起扣使用者 10 体力）；基础 CD 组合拳 60s／铁壁 60s／搂抱 55s，指令疲劳 ×(1＋1.5×已用次数)，我方再乘护腕 CD 倍率——**补上回合制引擎未消费的 cd 类装备机制**。

**KO/击倒执行层（判定规则不变，仅从「每交换结算」改为连续时间）**：
- 重创积累 traumaGain＝70 × 净伤 ÷ max(命中前 HP, 40%×最大 HP) × 拳种权重（刺 6／直 12／摆 18／上勾 18／击腹 12，÷12 归一）；被格挡未穿透减半；铁壁免疫；衰减 **6/秒**连续（替换回合制折算 1.5/交换）。
- 跨 25/50/75 刻度击倒：每刻度每回合只兑现一次（一拳跨多刻度只倒一次）；读秒 3 秒双方停手；起身 HP 回到至少 20%×maxHP（已高于时 +10%×maxHP 封顶）、体力 +20、双方连击清零、刻度标记跨回合重置。
- 终结仅四条：重创满 100 KO／HP 归零 KO／单回合 3 次击倒 TKO（死战开关照 web 口径、默认关）／点数判定（点数＝总伤害＋命中×2，打点战术命中项再 ×2，照 web pointsOf/finishBattle；平分按剩余 HP）。

**三模式共用方式**：
- 手动：玩家输入驱动我方（下节输入方案），对手走 foeTickManual 骨架。
- 自动观看：双方都走 tryAttack 概率节律，玩家保留战术切换＋三指令干预；预留速度倍率（1×/2×，web B.speed 同概念）。
- 模拟跳过：**不跑实时循环**，走 web 同构的解析标定模型（TTK 竞赛＋记分混合）：simMix/simNetPer/simAttempts 按引擎期望逐项建模（拳种混合、战术命中表、格挡折损只折我方进攻、体力 duty-cycle），常量用 P2 再标定值——winP logistic k=1.45／平移 0.52／α=1.50、记分 K=0.030、koP＝clamp(1.90 − 0.4125×minTTK)、SIM_FIT=1.10。实时引擎落地后须按 G3-a 同法对实测网格重新拟合（验收线见标定计划；已知结构性遗留：长局 KO 占比高估 12~20pp，随本次一并评估）。

### 风险

- **手感**：web 自动节律是概率掷骰的「半自动」味道，手动模式才是真操作；出拳 CD/射程照搬 web 手动表，但 60Hz 连续移动的手感（移速、最小间距、纵向偏移）属呈现标定，需实玩微调——可调，但不许借调手感改判定口径。
- **rig 动画密度**：实时出拳频率高于交换制，现有动画时长可能跟不上连打节拍——先用「新出拳打断旧动画」（web 帧序列同法），必要时在呈现层缩短动画时长，不动美术本体；人物不碎红线不变。
- **立绘卡对手（43 人）**：实时走位下静态立绘卡位移更显假——透明底立绘已按 2026-11-21 资源需求在生产，接入时配位移/受击动效兜底；根治仍待拍板①（补画侧面图与否）。
- **模拟漂移**：解析 sim 与实时引擎两套实现，历史上有 ±20pp 漂移教训——RT4 拟合与 RT5 跑批必须同批收官，不许先上线未标定的 sim。
- **回合制残留**：`TRAUMA_DECAY_PER_EXCHANGE`、`EXCHANGES_PER_ROUND` 等适配常量随旧引擎退役，`data/constants.json` 等处的引用一并清理；存档结构不动、老档兼容不受影响。
