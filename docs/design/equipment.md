# 装备设计（收缩版）

> 状态：**草案，待拍板**（`../DECISIONS.md` 待定 #4）。
> 现行实现：`godot/scripts/game_state.gd` 装备部分 + `godot/data/shop_gear.json`、`glove_*.json`、`materials.json`、`dismantle_map.json`。

## 1. 为什么要改

| 现状 | 问题 |
|---|---|
| 拳套 = 版型 × 外皮 × 内衬 × 盎司 × 固定方式，加定制、拆解、打造、强化 +10、图鉴 | 组合很多，但每项差 1~3 点属性，玩家感觉不到区别 |
| 战斗里看不见装备 | 装备最大的乐趣（好看）没了 |
| 材料 / 打造是很重的系统 | 钱本来就花不完，打造也没成为目标 |

## 2. 目标

- 装备要**看得见**（战斗、中枢立绘、结算）。
- 每件装备都有**一个明确的取舍**，选它就是选一种打法。
- 装备是**钱的主要出口**和**收集目标**。

## 3. 新结构

### 3.1 拳套（唯一有深度的装备）
三个维度，每副拳套在三角上有一个位置：

| 维度 | 偏这边的效果 | 代价 |
|---|---|---|
| 拳锋（硬） | 伤害 +，重创积累 + | 护手差：比赛后手伤概率 + |
| 护手（软） | 手伤概率 −，格挡时自己扣的体力 − | 伤害 − |
| 轻量 | 出拳冷却 −、体力消耗 − | 重创积累 − |

- 版型（守护 / 斗牛 / 经典）决定三角位置；**外观**（颜色、花纹）完全独立，可自由搭配。
- 盎司、固定方式、内外皮这些**保留为说明文字和图鉴条目**（真实感），不再单独算数值。

### 3.2 服装（纯外观 + 收集）
- 每套服装 = 战斗模型 / 精灵的一套外观 + 中枢立绘一张。
- 来源：商店、比赛奖励（拿到某个头衔）、成就、剧情。
- 目标数量：主角 8~12 套。对手每人 1 套比赛服（有余力加第 2 套）。

### 3.3 护齿 / 战靴
- 降为被动小加成（护齿：被击倒后起身概率 +3%；战靴：闪避体力 −10%），各 3 档，商店买断。

### 3.4 去掉 / 降级
- 强化 +10、拆解得材料、按配方打造：**去掉**。现有存档里的强化等级折算成「拳套品质」一次性加成。
- 「定制工坊」保留为高价外观定制（换颜色 / 花纹），作为后期钱的出口。

## 4. 经济挂钩

| 价位 | 内容 |
|---|---|
| ¥500~2,000 | 入门拳套、基础护具 |
| ¥3,000~8,000 | 中档拳套、普通服装 |
| ¥10,000~30,000 | 顶级拳套、限定服装、外观定制 |

和 `career.md` 的收入曲线一起调：目标是**第 20 周存款不超过 ¥5,000**，主要靠买外观花掉。

## 5. 存档迁移

- 老存档的拳套按版型映射到新三角；材料按市价折现成金钱；强化等级 → 品质加成。
- 迁移写进 `game_state.gd` 的读档迁移函数，冒烟测试加断言。

## 6. 验收标准

- 试玩：换一副偏「拳锋」的拳套后，玩家能说出「打得更疼但手容易伤」；
- 数据：第 20 周存款 ≤ ¥5,000（normal 策略机器人会买东西时）；
- 战斗画面里能看到拳套颜色变化。

## 7. 未决问题

- 服装要不要给极小的数值（例如「登场战袍：第一回合心态 +5」）？建议不给，保持纯外观。
- 对手的拳套颜色是否随她的阵营 / 赞助变化？
