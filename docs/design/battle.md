# 战斗设计（实时版）

> 状态：**草案**。视角已定＝背后视角（2026-11-21，试点对比见 `../playtests/CAMERA_PROTO_20261121.md`）；渲染路线（2D / 3D）仍待试点。
> 取代：Godot 回合制交换引擎（`battle_engine.gd` 的 `do_exchange`）。规则层沿用，见 §6。
> 上游：`../proposals/godot-desktop-2d.md` §6.5（从网页版提炼的实时数值基准）；参考：`../research/LOVEUPPER_ANALYSIS.md`、`../research/BLOOMBLOW_PLAYSTUDY.md`。

## 1. 体验目标（四条，所有设计都拿来对照）

1. **看得懂**：对手要出什么拳，有预兆；我打中了没有，一眼可见。
2. **打得到**：按下就出拳，0.1 秒内有反应；轻拳快、重拳慢，但慢的那一下打中了很疼。
3. **有后果**：打空重拳会露破绽被反击；体力耗光了手会变慢；一直挨打会倒地。
4. **有高光**：闪过一拳后的反击、击倒、读秒起身、最后一回合逆转——这些时刻要有专门的演出。

## 2. 视角与画面

- **背后视角**（已定）：镜头在主角**正后方**偏上，不偏开；主角占画面下方约 1/3，身体半透明虚化（盖住对手也没关系，用户 2026-11-21 确认），**拳套不透明**；对手正面朝向镜头，占画面高度 45~55%（视野角约 40°，或随距离推拉）。
- 擂台有纵深：远处围绳、观众；双方之间的距离用对手大小和地面阴影表现。
- 镜头语言（沿用现有 4 档打击反馈，只在大事件动镜头）：
  - 普通命中：不动；重击：1.5px 微震；
  - 击倒那一拳：推近 + 0.5 秒慢动作；
  - 必杀：压暗 + 横条特写 1.0 秒；
  - KO：慢动作 + 镜头绕到侧面看倒地（3D 路线才有）。

## 3. 操作

### 3.1 键位（键盘 / 手柄）

| 动作 | 键盘 | 手柄 |
|---|---|---|
| 左手（前手）拳 | J | X / □ |
| 右手（后手）拳 | K | Y / △ |
| 拳种修饰 | 无方向 = 刺拳 / 直拳；按住 W = 上勾；按住 S = 击腹；按住 A/D = 摆拳 | 左摇杆同方向 |
| 格挡（按住）| 空格 | RB / R1 |
| 高 / 低格挡 | 格挡 + W / S（低格挡防击腹、不防上段） | 格挡 + 摇杆 |
| 闪避 | Shift + A / D / S（左闪 / 右闪 / 下潜） | B / ○ + 方向 |
| 前进 / 后退 | W / S 双击（垫步） | 左摇杆双推 |
| 必杀 | L（能量满时） | LB + RB |
| 暂停 | Esc | Start |

所有键位走 Godot `InputMap` 命名动作，设置里可改。

### 3.2 节拍（参考 Love Upper 60fps 帧数据，单位：秒）

| 拳种 | 前摇（到顶） | 收招 | 空挥惩罚 | 伤害系数（用户硬数字） |
|---|---|---|---|---|
| 刺拳 | 0.05 | 0.15 | 无 | 0.6 |
| 直拳 | 0.10 | 0.37 | 小 | 1.2 |
| 摆拳 | 0.17 | 0.50 | 大（开反击窗口） | 1.4 |
| 上勾 | 0.18 | 0.48 | 大 | 1.3 |
| 击腹 | 0.27 | 0.45 | 中 | 0.8（穿透格挡 70%） |

规律（逆向结论 1）：**轻重拳的差别主要在收招，不在前摇**。打空重拳的代价是 0.5 秒动不了。

### 3.3 防守

- **格挡**：按住生效，伤害 ×0.3、重创只积一半、每次被打中扣 3 体力；高格挡防不住击腹（击腹穿透 70% + 1.5 秒破防）。
- **闪避**：方向闪避，无敌 0.3 秒，体力 15，冷却 1.5 秒。闪对方向 → 开 **1 秒反击窗口**：对应拳种（左右闪 → 摆拳，下潜 → 上勾）+40%，其余 +30%（用户硬数字）。
- **闪错方向**：照样挨打，并且多 0.2 秒硬直。

### 3.4 读招（「看得懂」的关键）

- 对手每种拳都有 **0.25~0.5 秒的预兆**（肩膀后拉、重心下沉、拳套抬起），难度越高预兆越短：新人赛 0.5 秒 → 冠军 0.25 秒。
- 新人期额外有提示（对手出拳侧的拳套闪一下光），设置里可关。
- 每名对手有 2~3 个**习惯**（例：「连续两记刺拳后必接右直拳」「体力低于 30% 爱抱架」），赛前侦察（录像研究训练）会揭示其中一条。

## 4. 资源

| 资源 | 规则 |
|---|---|
| HP | 100 + 耐久 × 14；归零 → 击倒读秒（方案 B） |
| 体力 | 上限 100；出拳 / 闪避消耗，移动中 3.5/s、静止 7/s 回复，格挡中不回；低于 30 时出拳冷却 ×1.4、伤害 ×0.75 |
| 重创 | 累计到 25 / 50 / 75 各击倒一次（每刻度每回合一次），满 100 KO；衰减按秒连续 |
| 必杀能量 | 命中、闪避成功、反击成功攒能量；满了按 L 放本角色专属连招（每场至多 2 次） |

## 5. 对手 AI

- **大脑**：目标距离（按风格：力量型贴近、速度型游走、防反型等反击）+ 出拳计时器 + 习惯脚本 + 指令（铁壁 / 搂抱 / 组合拳，§6.5 已有规则）。
- **难度不靠加属性，靠缩短预兆和减少空挥**：新人期对手经常打空大拳，给玩家反击机会；冠军几乎不空挥。
- 回合间按点差变招（领先转稳守、落后转强攻，门槛 ±20）。

## 6. 规则层（保留，数值不动）

> 已实现：`godot/scripts/battle/battle_core.gd`（2026-11-21）。标定面定稿 HP 池 ×3.0、重创衰减 0.55/秒，1002 场全部验收线达标，见 `../playtests/RT_CORE_20261121.md`。

伤害公式、减伤封顶 70%、重创增长 K=40、跨刻度击倒、方案 B 读秒（起身概率 0.40 + 意志×0.007 + 体力×0.003 − 已倒次数×0.10，起身回 35% HP）、同回合 3 倒 TKO、点数判定——全部沿用当前引擎。只有两处换成「按秒」：重创衰减、回合时长（3 回合 × 60 秒，回合间休息 30 秒）。

**用户硬数字（不可擅改）**：连击加成 +5/+15/+25%、反击窗口 +40%/+30%、击腹穿透 70%、拳种基础系数 0.6/1.2/1.4/1.3/0.8。

## 7. 三种模式共用一个内核

| 模式 | 我方 | 对手 | 玩家能做什么 |
|---|---|---|---|
| 手动 | 玩家输入 | AI 大脑 | 全部操作 |
| 自动观看 | AI 大脑（按所选战术） | AI 大脑 | 切战术、下指令、1× / 2× 速度 |
| 模拟跳过 | 不跑实时，用解析模型直接出结果 | — | 只看战报 |

模拟模型要和实时实测对拟合：同阵容胜率差 ≤ ±15 个百分点。

## 8. 回合间指导

半透明面板，30 秒倒计时（可跳过）：
- 上方：教练一句话 + 本回合数据（命中率、被击倒次数）；
- 中间：**4×2 指令格**——战术（强攻 / 均衡 / 稳守 / 打点）+ 处理（止血、冷敷、调整呼吸、鼓舞），每回合选 2 个；
- 右侧：主角立绘卡，表情随状态变化。

## 9. 呈现分层

```
BattleCore（规则，固定 60Hz 步进，可设随机种子，无画面也能跑）
  ├─ 发事件：punch_started / hit / blocked / dodged / whiff / knockdown / round_end …
  └─ Presentation（只订阅事件，不改规则）
       ├─ 角色表现（2D 精灵或 3D 模型，二选一，见 §10）
       ├─ 打击反馈（顿帧 / 特效 / 音效，现有 4 档）
       └─ HUD / 演出（读秒、K.O.、连招名、必杀特写）
```

这样同一套规则可以被试玩机器人无画面批量跑（平衡测试），也可以换渲染路线而不动规则。

## 10. 渲染路线试点（决定 2D 还是 3D）

> 2026-11-21 已做第一轮：2D 用现有单张立绘、3D 用 VRoid CC0 样例模型，结果和建议见 `../playtests/RENDER_PROTO_20261121.md`（Claude 建议 3D，待用户定）。下表是完整试点（按我们的角色做模型 / 补画姿势）的规格。

**试点内容**（两条路线做同一件事）：主角 vs 1 名对手（林小葵），打满 1 回合；动作至少有：待机、刺 / 直 / 摆 / 上勾 / 击腹、格挡、三向闪避、轻 / 重受击、倒地、起身。

| 路线 | 做法 |
|---|---|
| B 2D 精灵 | 对手正面 12 张、主角背面 12 张（muse 生成），整帧切换 + 程序位移 |
| C 3D 卡通 | VRoid Studio 做 2 个模型 → Godot VRM 插件导入 → 卡通着色 + 描边；动作用 Mixamo 拳击动作重定向，缺的自己调关键帧 |

**评估表**（每项 1~5 分，你和我各打一份）：

| 项 | 说明 |
|---|---|
| 像不像我们的角色 | 和现有立绘比，脸和发型认不认得出来 |
| 打击感 | 命中、受击、倒地的力度 |
| 动作流畅 | 连打时有没有跳帧、卡顿、穿模 |
| 加一个新角色要多久 | 实际计时 |
| 换装 / 换拳套要多久 | 实际计时 |
| 崩坏风险 | 撕裂、穿模、风格不一致 |

总分高的定为正式路线，写进 `DECISIONS.md`。

## 11. 验收标准（实现后怎么算做完）

**数据（试玩机器人批量跑，`process/TESTING.md`）**
- 终结分布：判定 ≥ 30%，KO + TKO ≤ 70%，没有一种 > 60%；
- 势均力敌胜率 40~60%；+6 属性优势胜率 ≥ 75%；
- 平均终结回合 ≥ 2.2。

**手感（真人试玩问卷，每项 ≥ 4/5 才通过）**
- 我能看出对手要出什么拳；
- 按键到出拳没有延迟感；
- 闪过之后的反击很爽；
- 被击倒时我很紧张；
- 输了我知道是哪里打错了。
