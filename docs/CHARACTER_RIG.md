# 比赛中人物动态化方案（CHARACTER_RIG）

> 问题（用户 2026-11-03 提出）：比赛中人物还是纯贴图——只有主角有姿势帧，对手全程一张站姿图。目标：所有参赛角色在比赛中至少有 2D 建模（骨骼/关节）级的动态表现。
> 本批范围：审计＋两条路线原型验证＋分阶段落地方案。**未改任何正式战斗代码**；原型在 `~/workspace/.pwtest/rig_proto/`，截图在 `~/workspace/.pwtest/rig_proto/shots/`。
> 实测对象：opp_asia（抱架站姿、双拳相对独立、四肢分离度好，是 52 名角色的典型形态）。

---

## 一、现状审计（已核实）

| | 主角 | 对手（50 人＋前辈＋经纪人） |
|---|---|---|
| 素材 | `web/assets/pose/` 10 帧姿势图（guard/jab/straight/hook/upper/body/block/dodge/hit/victory，700×1004） | 单张去底立绘 `web/assets/opponents_alpha/*.webp`（700×1004，全 50 份共 4.0MB，均 76KB/张） |
| 演出手段 | 姿势帧切换（`setMePose`，出拳 250ms／受击 320ms／格挡 300ms／闪避 320ms）＋整图变换 | **只有整图 CSS 变换**：`bob` 待机上下浮动、`.punching` 前冲、`.hit` 抖动、`.recoiling` 后仰、`.down` 整体旋转 82° 倒地、残影、击退位移、距离走位（left%） |
| 缺什么 | 姿势是整帧替换、无帧间过渡；倒地仍是整图旋转 | **姿势永远不变**：出拳不伸臂（整个人前冲代替）、受击不缩身、格挡无姿势差、被击倒＝站姿图躺平。52 人全同病 |

补充事实：

- 全体源图都是**正面抱架站姿**（双臂屈肘、拳套贴近脸/胸）。这一条同时决定了两条路线的难度分布（见下）。
- 战斗时序锚点：出拳 250ms、受击 320ms（`POSE_TIMING`），任何动态方案都要能在这两个窗口内起落。
- 同屏只有 2 名角色；目标设备中端安卓；PWA 对包体积敏感；「减少动效」设置必须能退回静态。

## 二、路线 A：程序化网格变形（整图活化）——实测结论

**做法**：Canvas 2D 把单张立绘切成 40 条水平切片逐条 `drawImage`，顶点偏移由姿态参数驱动：弯折曲线（顶部偏移 ∝ (1−y)^1.6）、胸带高斯窗呼吸缩放、纵向压扁（脚底锚定）、整体旋转＋落点补偿。原型：`rig_proto/routeA/index.html`（可打开、按钮切换四态、带 fps 计量）。

**四态实测**（截图 `shots/A_guard.png / A_punch.png / A_hit.png / A_hitx.png / A_down.png`）：

| 状态 | 参数 | 观感结论 |
|---|---|---|
| 待机呼吸 | 胸带横向 ±2.2% 正弦＋整体 ±1.5px 浮动 | 静态图看不出、动起来明确「活着」；与现有 CSS `bob` 是质变（身体内部在动，不是整图平移） |
| 出拳前冲 | 前倾弯折 −46px＋前移 30px＋横拉 1.07 | 读作「整身扑出去打」，轮廓完整无接缝；**但拳还是不伸**——这是 A 的硬上限，只能靠速度线/残影补气势 |
| 受击后仰 | 弯折 +54px＋压扁 0.97 | 平滑可信，脸和发丝不变形失真；在 320ms 窗口里完全够用 |
| 受击·极限 | 弯折 +120px（源图坐标） | 仍无撕裂/阶梯（40 切片下偏移连续）；退化形式是**整体柔化＋斜向剪切**：腰带、短裤的图案开始被剪歪，文字类细节会糊。可用弯折上限 ≈ 头部位移 90~110px（源图），日常受击用 40~60px 有充足余量 |
| 被击倒 | 旋转 82°（脚侧枢轴）＋压扁 0.86 | 身体完整躺平，与现行 CSS `.down` 同级或更好（多了压扁回弹）；注意倒地后占宽≈身高，舞台布局要给落点留位（现行方案同样有此约束） |

**性能**：单角色 40 次 drawImage/帧；无头 Chromium 下 CPU 节流 6× 仍顶格 60fps（无头环境 vsync 封顶 60，此为下限证据而非上限）。双角色 80 次/帧对 Canvas 2D 是轻载，中端安卓稳 60 的把握大；不需要 WebGL。

**对接难度**：低。姿态参数就是几个数值，现行事件（出拳/受击/格挡/闪避/击倒/起身）一一映射为参数包＋过渡时长（250/320ms 直接复用 `POSE_TIMING`），可与现有 DOM 结构共存（每名角色一块 canvas 或整场一块 canvas）。「减少动效」时呼吸置 0、过渡改瞬切即退化为现行表现，无额外分支。

**观感上限（一句话）**：能让 52 个人全部「活过来、挨打有反应、倒地像倒地」，但关节永远不动——出拳仍是整身前冲，达不到用户说的「2D 建模」感，只能算 1.5D 活化。

## 三、路线 B：真 2D 骨骼纸偶（拆件绑定）——实测结论

做了两条子路：**(B1) 从现有立绘程序化拆件**、**(B2) 按绑定规格直接生图拆件**。

### B1 程序化拆件＋最小骨骼（原型 `rig_proto/routeB/`，切割脚本 `cut.py`，演示 `index.html`）

拆法：人工多边形（头/双上臂/双前臂含拳套/双腿/躯干残差）→ 掩膜扩张重叠 → alpha 饱和羽化 → 同坐标系部件；骨骼层级 root→torso→{head, 上臂→前臂}、root→双腿；关键帧插值驱动四动作。两轮调参后的量化与观感：

- **静止重组**：与原图平均误差 0.83/255（第一轮 1.6，靠「扩张 13px＋羽化 1.6px＋alpha×1.8 饱和＋残差认领阈值 0.3」修掉透光带）——静止与待机微动（±2°）目视无缝。✅
- **待机/受击（小角度）**：头颈、躯干后仰、手臂下沉都成立（`shots/B_guard.png / B_hit.png`）；但手臂外张 >约 10° 后，拳套原先遮住的胸口会露出**楔形空洞**（原图根本没画被遮挡的身体——残差法无米下锅）；躯干旋转 5.5° 时裤脚与腿之间仍有约 10px 级细缝（重叠量需 ≥ 枢轴距离×最大转角，第一轮 9px 不够、13px 勉强）。⚠️ 可用但要靠「补绘底层」根治。
- **出拳（大角度伸臂）**：**不成立**（`shots/B_punch.png`）。三重几何冲突：①源图拳套是正对镜头的拳面，刚性旋转 80° 后变成「拳头翻着手腕甩出去」，不是伸直的拳；②屈肘姿势切出的前臂件带着弯曲的轮廓，转正后肘部楔形缺口＋腕带错位；③上臂件顶部（被拳套挡住的肩部）一转就露出没画完的断面。怎么调轨道参数都绕不过去——**问题在素材形态，不在绑定技术**。
- **击倒**：root 整转＋四肢散落成立（`shots/B_down.png`），与 A 同级以上（四肢能各自摊开）。✅

### B2 按绑定规格生图（`rig_proto/routeB/gen/`，一次实测）

让生图管线按「双臂伸直展开、部件分离平铺、圆头关节端」的规格重绘同一角色拆件图。结果：**布局概念一次到位**（头/躯干/上下臂/前臂拳套/大腿/小腿鞋分件齐全，甚至自带关节球），证明规格化生图的方向是通的；但**不能直接用**：

1. 白底而非透明底（可抠，但多一道工序且发丝边缘要修）；
2. **角色身份漂移**：脸型、发型细节、肤色渲染都被重绘成「像她但不是她」，与剧情立绘并排会出戏；
3. 缺件与错件：躯干只剩上衣（腹部/腰带整段丢失）、左右小腿鞋同侧、关节球画成独立浮圆、上臂退化成光杆——单次生成无注册（各件比例互不对齐，拼装要逐件缩放对位）。

结论：生图可作 B 的**草稿来源**，每件需 2~4 次抽卡＋人工修整对齐，达不到「一键 52 人」。

### B 的工作量与一致性风险（全量 52 人）

- B1 纯拆现有图：每人多边形标定＋调枢轴 ≈ 20~40 分钟（需小工具辅助），52 人 ≈ 20~35 小时纯标定，且**出拳动作全员不合格**（素材形态问题，与标定精度无关）——此路只能支撑待机/受击级动态。
- B2 重生＋修整：每人 1.5~3 小时（抽卡、抠图、补缺件、对齐、绑骨、验动作），52 人 ≈ 80~150 小时，且每人都有身份漂移风险，需逐人目视验收；比赛美术与剧情立绘从此是「同一角色的两套画」，一致性靠人盯。
- 一套骨骼数据复用：**可行**。骨骼模板只存「9 个地标的相对坐标＋分段长度比」，体型差异靠每人一次地标标定吸收（本原型 opp_asia 的枢轴即是手工标定的）；发型/服装差异天然保留在部件图里。例外需逐人覆写：超长发（头发要不要第二骨节）、披风/裙摆类遮挡、体型极端者（如 opp_muscle 的肩宽）。

**观感上限（一句话）**：素材按绑定规格重做的前提下，B 是唯一能达到「真伸臂出拳、关节在动」的路线，上限远高于 A；但拿现有成品立绘硬拆，上限被素材形态锁死在「待机＋受击」级别，出拳必露馅。

## 六、试点实装记录（主角，2026-11-04，用户拍板先做主角一人＋骨架全员共用模板）

> 路线修正：未走 B2「整套生图拆件」，实际走通的是 **B1 改造版——从既有定稿姿势图（guard/straight，均带真 alpha）按骨骼规格切件＋程序化补绘**。身份零漂移（部件就是原图像素），且避开了 B2 的抽卡一致性问题。B1 原型「出拳必露馅」的三大症结（拳面翻腕、屈肘楔形缺口、肩部断面）靠三条规则根治：①前臂件从**伸直出拳帧（straight）**取材（源图本就是伸直形态，不存在弯臂轮廓）；②全员部件统一**右朝向**（guard 是左朝向图，头部切件后水平镜像，马尾正好甩向身后，与 straight 一致）；③子骨骼原点定义在**父骨骼绘制帧**（父原点＋父段长∠父绘制轴向），FK 闭合验算误差归零（早期用组装舞台坐标作子原点是首轮校准散架的主因）。

### 部件生产实际流程（源文件在 `assets/rig_me_src/work/`，可复现管线）

1. `extract.py`：多边形从 guard/straight 切 8 件全画布同坐标 PNG（头/远小腿←guard，其余←straight）；头部在此步镜像。
2. `extract_torso2.py`：躯干单独从 straight 切（抱架图躯干遮挡过重，v1 已证失败勿再试）：多边形填充＋多尺度扩散修补手臂遮挡带（取色源排除近白光晕 min(RGB)>205）＋重绘胸前三颗星＋肩带区阴影渐变压暗（防出拳时露硬边）。
3. `fix_head.py`：擦除抱架图混入头部的拳套碎片＋在头部底层补绘颈部（羽化肤色块，解决下颌—肩带间空洞；摆拳/上勾时一度露硬边，缩小＋blur 3.5 后解决）。
4. `crop_parts.py`：按 alpha 包围盒裁切＋写 `parts/meta.json`（裁切框/枢轴/轴向/段长）。
5. 交付转换：PNG 母版（`assets/rig_me_src/`）→ webp 88 质量进 `web/assets/rig/me/`，**8 件共 84,468 字节**。
- 生成调用：media 生图仅 2 次（头部候选 1 次成功、躯干 1 次未完成）；最终部件**全部来自既有定稿图程序化切件**，生成图未采用（生成的正侧面头与 guard 的 3/4 视角不一致）。耗时大头在校准迭代（约 9 轮截图修正：求解器父链累加 bug、子原点帧错误、姿势左右帧混用、倒地世界角、freeze 的 NaN bug 各一轮）。

### 骨架模板数据结构（`web/js/rig.js`）

- `RIG_TEMPLATE`（全员共用）：`frame=[700,1004]`；`bones` 10 根 [名, 父, 部件键, 绑定帧原点, 远侧压暗]（层级 root→腿、root→躯干→{头, 上臂→前臂}）；`segRatio` 分段长度比（以躯干长 250 为 1.0：上臂 .730/前臂 .854/近大腿 .592/近小腿 .743/远大腿 .547/远小腿 .605）；`poses` 14 个姿势（世界方向角编写：肢体=段指向角、躯干/头=世界旋转角，引擎按骨链换算局部角）；`anims` 13 个动作（时序对齐 POSE_TIMING：出拳 250ms/受击 320ms 等；`stance` 键在播放时按当前架势 guard/block 解析）。
- `RIG_CHARS.me`（单角色标定）：部件目录＋每件 `box/pivot/axisDeg/len`。新角色扩围只产出这一份数据＋部件图，动作/姿势零改动。
- 标定步骤（每名新角色）：①选其伸直出拳帧与抱架帧（同朝向、带 alpha）；②按主角多边形模板比例切 8 件，遮挡带扩散修补；③量各段两关节点得 axisDeg/len 与枢轴，写入 meta；④按模板 segRatio 与其立绘地标微调 `bones` 原点（体型差吸收在此步）；⑤校准页逐姿势目检（出拳峰值/受击/击倒必查）。

### 接入与回退

- `battle.js`：`setMePose` 双路驱动（姿势图 src 照常切换作回退层＋冒烟锚点；同名驱动纸偶：guard/block 架势、五拳种同名动作、hit 按 figMe 是否带 .down 分流 down/hit、起身 getup、victory）。顿帧/慢动作经 `rigTimeScale()` 读 ring 的 frozen/slowmo 类（0 / 0.35）。残影在纸偶模式改为克隆纸偶 DOM 快照。出拳 CSS lunge 只挂姿势图、纸偶靠姿势内 root 位移，二者不叠加。
- 回退开关：`battle.js` 的 `ME_RIG` 常量，置 false 即恢复姿势帧（已实测：rig-on 不加、img 可见、guard 图正常，截图 `g_fallback.png`）。
- CSS：`#figMe.rig-on` 下隐藏姿势图、关 bob/.down 整图旋转，受击红闪转挂 `.rig-host`，shake/stumble 保留在 .fig 层。
- 「减少动效」：建 rig 时读 SETTINGS.reduceMotion（呼吸关、动作直接落终点帧）；战斗中途改设置于下一场生效。
- 换装：本批不接纸偶（与姿势帧同口径，战斗用标准比赛服一套）。
- SW 版本已递增 boxing-pwa-v20。

### 每新增一名对手的预估工时（外推）

- 有现成同朝向「抱架＋伸直出拳」两帧立绘时：切件＋修补 ≈ 40~70 分钟（管线脚本已有，主要是多边形适配与遮挡修补）、标定＋校准目检 ≈ 20~30 分钟，**合计约 1~1.7 小时/人**。
- 缺伸直出拳帧（多数对手现状只有单张站姿）：需先补一张出拳帧素材——若走生成＋修整，按 B2 实测每人再加 1~2 小时且带身份漂移验收成本。建议扩围顺序仍按「重点角色优先」，且先给目标角色补出拳帧素材再绑骨。

### 遗留问题

- 长发（马尾）无第二骨节：摆动靠头部骨骼旋转整体带动，剧烈动作时发尾略显刚性。
- 击腹/摆拳为同臂链不同轨迹近似（无横向弧线扫掠的中间帧形变），靠躯干配合与时序区分，可辨但非逐帧考究。
