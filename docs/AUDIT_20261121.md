# 全面审核：离「可发布」还差什么（2026-11-21）

> 审核对象：Godot 桌面版（`godot/`，主线）。网页版只当原型参考，不再审。
> 依据：本人当日实跑（20 周自动试玩、720 场 KO 探针、UI 截图）、代码与数据盘点、Love Upper 逆向结论（`research/LOVEUPPER_ANALYSIS.md`）、Bloom Blow 试玩观察（`research/BLOOMBLOW_PLAYSTUDY.md`）。
> 结论先行：**系统骨架已经齐了（养成、排名、装备、剧情、成就、存档都能跑），离发布差的主要是三件事——①战斗要从「点按钮的回合制」改成真正的实时拳击；②人物表现要换成能撑起实时战斗的方案（建议试 3D）；③要有一个完整的「开局 → 结局」生涯弧线和发布必需的外围（设置、教程、署名、安装包）。**

## 1. 到「完成」还需要哪些东西（总清单）

**必须有，否则不能发布**
1. 实时战斗（手动可玩、自动观看、模拟跳过三模式共用一个内核）——见 §4。
2. 一套能撑起实时战斗的角色表现：所有出场对手都要能动、能被打、能倒地——见 §5、§6。
3. 完整生涯弧线：明确的终点（例：世界冠军 / 退役）和结局画面——见 §2。
4. 设置界面：音量（BGM / 音效分开）、全屏 / 窗口、分辨率、键位说明（最好可改键）、手柄支持。
5. 暂停菜单（战斗中 Esc）、存读档界面（3 槽已有逻辑，要有正经 UI）。
6. 新手引导：序章已有，但实时战斗需要一场「教学赛」。
7. 致谢页（游戏内）：CC BY 3.0 的 Soundholder 必须署名；所有素材来源要清楚。
8. 安装包：Windows 导出 + 版本号 + 图标 + 发布页（itch.io）。
9. 52 名角色正式命名、文案终审（OPEN_ISSUES 里遗留的 110 条待审）。

**应该有（决定好不好玩）**
- 赛前 VS 演出、回合间指导面板、赛后结算横幅（Bloom Blow 已验证的格局）。
- 宿敌线：同一个对手反复遇到时要有剧情，而不是「又输给她一次」。
- 训练要有一点互动（小游戏或至少有动画反馈），否则日常就是点菜单。
- 服装收集（Love Upper 的核心乐趣之一）。

**可以以后再说**
- 捏人 / 自创角色（网页版 Phase 6 有雏形，Godot 未移植）。
- 世界赛 / 多团体头衔 / 体重级。
- 英文版。

## 2. 设计缺哪些

### 2.1 生涯没有终点
- 现状：6 个阶段，最后一个是「传奇之路」，之后就是无限卫冕。
- 问题：一款要发布的游戏需要一个**能讲完的故事**和明确的「通关」时刻。现在玩家不知道自己在往哪走、什么时候算赢。
- 建议：主线定为「约 40~60 周拿到国内冠军 → 冲世界冠军 → 结局」，通关后进入自由模式（继续卫冕）。加入**退役压力**（累计被 KO / 重伤影响后期属性，Bloom Blow 的做法），让生涯有长度上限和紧张感。

### 2.2 开局太难、中段卡墙
- 实测：第 1 周属性约 15，三个候选对手里两个胜算只有 5~8%；试玩机器人常对同一人连输 4~5 次，然后一口气升 6 名。
- 输了几乎没代价（不掉名次、有奖金）——所以「卡墙」不是惩罚问题，是**梯度问题**。
- 建议：对手候选按胜算排一个「稳 / 五五 / 冒险」梯度；冒险赢了奖励翻倍；连输同一人时触发宿敌剧情 + 侦察提示。

### 2.3 经济失衡
- 第 20 周 ¥17,708，没有值得花的东西。
- 建议：钱的出口要和「变强」或「好看」挂钩——服装 / 拳套外观收集、教练 / 陪练雇佣（提高训练效率）、医疗（加快伤病恢复）、集训营（一周特训）。同时检查打工收入是否过高。

### 2.4 日常太「菜单」
- 每天：点训练 → 选项目 → 结算数字。13 种训练只有数值差别。
- 建议：至少 3 种训练做成 10~20 秒小游戏（手靶节奏、速度球连按、闪躲球反应），表现好给加成、可跳过（自动按平均值）。这也是给实时战斗做操作预热。

### 2.5 养成看不见
- 属性涨了，角色外观和动作没有任何变化。
- 建议：熟练度到一定档位，对应拳种动画变快 / 出残影（原设计「五之二」就写了，但没做）；中枢立绘随阶段换装。

### 2.6 剧情与关系薄
- 46 段剧情 + 29 段日常都是文字弹窗。4 名可攻略角色只到「心动暗示」。
- 建议：每名重点角色 1~2 张事件 CG；赛后败北 / 胜利事件（Bloom Blow 情绪最强的一环）；给生涯结局 3 种分支（看关系和成绩）。

## 3. UI / 画面设计欠缺

| 问题 | 现状 | 要做 |
|---|---|---|
| 统一美术方向 | 标题画面紫粉霓虹，中枢刚换上 muse 素材，战斗 HUD 还是默认样式 | 写一份 UI 风格规范（颜色、字体、按钮、面板、图标、动效），所有界面按它改 |
| 文字太多 | 中枢左下是滚动日志，右侧大段说明 | 日志收进「通知」；属性、状态都用图标 + 条形图；说明改成悬停提示 |
| 没有转场 | 界面之间瞬切 | 淡入淡出 / 滑动，比赛进场要有 VS 演出 |
| 战斗 HUD | 三条直条 + 数字百分比 | 头像 + 分段体力（Bloom Blow 的花形图标思路，我们换成心形 / 拳套） + 回合钟 + 战术名 |

## 4. 战斗设计（核心问题）

### 4.1 现状
- 战斗是**回合制交换**：每回合 14 次交换，每次玩家从按钮里选一种拳或一种防守（格挡 / 闪避 / 硬扛），引擎掷骰结算。
- 规则层（伤害公式、重创、击倒读秒、TKO、点数）已经标定好：方案 B 后判定 48% / KO 32% / TKO 19%，势均力敌胜率 45~55%。
- 呈现层：整帧精灵侧视，打击特效 4 档、真实音效、读秒和 K.O. 演出都有。

### 4.2 问题
1. **没有「操作」**：玩家做的是选择题，不是打拳。没有距离、没有时机、没有看穿对手。你说的「实时感、互动感」根本上缺在这里。
2. **侧视不适合实时拳击**：侧视适合观看（Bloom Blow 是模拟观战），不适合亲手打——两个人在同一条线上，闪避只能前后，出拳方向看不清。
3. **呈现撑不住实时**：实时战斗每秒都要切姿势，主角只有 10 张图，42 名对手只有 1 张图。

### 4.3 结论：战斗模式要改
- **改成实时**（2026-11-21 你已拍板过，proposal `godot-desktop-2d.md` §6.5 有移植方案）。
- **再进一步建议：改成「背后视角」**——镜头在主角身后偏上，对手正面朝向镜头。这是实时拳击游戏最常见的视角（第三人称跟在拳手身后）。理由：
  - 闪避有左 / 右 / 下潜三个方向，玩家一眼看懂；
  - 对手的出拳「冲着你来」，打击感和压迫感比侧视强得多；
  - 对手大、正面，表情和受击反应看得清——美少女题材最该展示的就是这个；
  - 美术上，**对手只需要正面姿势、主角只需要背面姿势**，比侧视要的「每人每个姿势都要画」省一半。
- 规则层（伤害 / 重创 / KO / 点数）全部保留，只换输入和节拍。详细方案见 `design/battle.md`。

## 6. 人物：要不要重新做立绘 / 建模

**立绘（中枢、剧情、选人、商店）——保留。** 50 人同画风，已经是项目最好的资产。只修瑕疵（光晕、发色）+ 补事件 CG。

**战斗用的角色——要换方案。** 现在的「每人每姿势画一张」是线性成本：50 人 × 至少 20 个姿势 = 1000 张风格一致的图，AI 生成也很难保证一致（项目之前的抠帧管线就是因为这个放弃的）。

三条路线对比：

| 路线 | 做法 | 每加 1 个角色的成本 | 打击感 / 镜头 | 装备 / 换装 | 风险 |
|---|---|---|---|---|---|
| A 侧视 2D 精灵（现状） | 每姿势一张整图 | 20+ 张一致的图 | 弱 | 每套装备要重画 | 美术量爆炸 |
| B 背后视角 2D 精灵 | 对手画正面姿势、主角画背面姿势 | 约 12 张正面图 | 中 | 每套装备要重画 | 一致性仍难 |
| **C 3D 卡通渲染（建议试点）** | VRoid Studio 做二次元模型（免费、导出 VRM）→ Godot 导入 → 所有人共用一套拳击动作（Mixamo 免费动作 + 自制） | **1 个模型**，动作全员共享 | 强：推镜、慢动作环绕、受击叠加动作 | 拳套 / 衣服换颜色或换网格，几乎零成本；捏人系统顺带有了 | 模型风格要贴近现有立绘；VRoid 需要人工操作 |

C 路线正是 Love Upper 的做法：11 人共用一套骨骼和 358 段动作，靠换模型和贴图扩角色（见逆向结论）。Godot 4 有现成的 VRM 导入插件和人形骨骼重定向。

**建议**：先花 1~2 周做一个**战斗试点**——同一套实时规则下，用 C 做主角 + 1 名对手打一场，用 B 做同样一场，按 `design/battle.md` 里的评估表对比后再定。这是整个项目最大的一个分岔口，定了再大规模生产。

## 7. 装备系统：保留还是只做外观

**现状**：拳套 = 版型 × 外皮 × 内衬 × 盎司 × 固定方式，加定制 / 拆解 / 打造 / 强化 +10 / 图鉴。21 件商店装备 + 材料系统。

**问题**
- 战斗里看不见（整帧精灵没有换装）。
- 数值差异小、组合多，玩家很难感觉到「这副拳套让我打得不一样」。
- 打造 / 拆解 / 强化是很重的系统，但经济上钱又多到花不完——系统深度和它的作用不匹配。

**建议：保留，但收缩成「外观 + 少量有取舍的数值」**
- 拳套保留 3 个有明确取舍的维度：**伤害 ↔ 护手（受伤风险）↔ 速度 / 体力**。去掉强化 +10 和拆解材料链（或降为可选的高级玩法）。
- **外观是重点**：拳套颜色 / 花纹 / 服装在战斗中看得见（走 C 路线时几乎免费）。服装做成收集要素，靠比赛 / 成就 / 商店解锁——这也是钱的出口。
- 护齿、战靴降为被动小加成，不再单独做深系统。
- 详见 `design/equipment.md`。

## 8. 其他发现

- **工程**：`main.gd` 已 9 万字节、所有界面写在一个文件里，后面改 UI 会越来越难。建议在战斗重做前把界面拆成独立场景（中枢 / 商店 / 比赛 / 战斗 / 设置）。
- **测试**：已有冒烟测试（`dev/smoke_test.gd`）、试玩机器人（`dev/playtest.gd`）、KO 探针、截图脚本——这是好基础。缺：真人试玩的流程和反馈表。
- **未提交的东西**：Godot 4.7.2 改写的约 61 个 `.import` 文件、未使用的挥空切片——建议一次性决定（`.import` 提交，未用切片删掉或移出仓库）。
- **文档**：旧文档 40 多份、大部分是网页版时期的，已归档到 `archive/web-prototype/`，新入口是 `docs/README.md`。
