# Phase 9：多存档槽（2026-11-02）

解决「单槽开新档顶掉老档」的风险：玩家可在 3 个存档槽之间切换、互相备份，重新开始只清当前槽。实现位于网页工程 `web/`（js/game.js 存档区段、js/ui.js 顶部栏渲染、index.html 顶部栏与弹窗、css/main.css 槽卡样式），存档结构 `S` 未改，`save()` / `load()` 与已有冒烟对 `SAVE_KEY` 的直接读写全部保持兼容。

## 最终 key 方案（槽位交换）

| key | 含义 |
|---|---|
| `boxing-phase1-save-v1`（SAVE_KEY) | **当前槽的本体存储**。所有既有读写路径（save/load、测试档备份/恢复、已有冒烟断言）不变，操作的永远是它 |
| `boxing-phase1-save-v1-meta` | 元信息：`{ current: 1~3 }` 当前槽号。缺失/非法 → 默认槽 1，**老存档零迁移自动成为槽 1** |
| `boxing-phase1-save-v1-slot1` / `-slot2` / `-slot3` | 各槽的**离槽暂存位**：只存放非当前槽的进度。当前槽的暂存位无意义且在切入时删除，防止读到过期副本 |
| `boxing-phase1-save-backup-v1`（BACKUP_KEY) | 测试档专用备份（既有），前缀与槽 key 不冲突，不动 |

取舍说明：任务原案设想「槽 1 本体即 SAVE_KEY、无需暂存位」，但切换离开槽 1 时其进度必须有落点、且不能与当时作为当前槽本体的 SAVE_KEY 混用，因此最终给槽 1 也设暂存位（仅在它不是当前槽时使用）。这样三槽逻辑完全对称：**当前槽看 SAVE_KEY，非当前槽看各自暂存位**，摘要、切换、复制都按这一条不变量实现，无特例分支。

## 切换 / 复制流程

切换（`switchSlot`，UI 经 `confirmSwitchSlot` 确认框）：
1. 守卫：目标=当前槽、或测试档锁定中 → 直接返回/提示；
2. `save()` 先把内存最新进度落进 SAVE_KEY；
3. SAVE_KEY 原文 → 旧槽暂存位；目标槽暂存位原文 → SAVE_KEY（并删目标暂存位）；目标为空则删除 SAVE_KEY；
4. 写 meta 当前槽号；
5. 收尾（停战斗、清剧情队列与序章状态、关弹窗，与「重新开始/恢复主存档」同口径），有档走现有 `load()` 重新载入 + 成就静默追溯；空档/读档失败 → `defaultState()` 新档初始化，render 后若序章未完成则 `startPrologue()`——空槽切换等同新游戏，序章照常，且切回原槽进度完好。

复制（`copyCurrentToSlot`，UI 经 `confirmCopySlot` 确认框）：`save()` 后把 SAVE_KEY 原文写入目标槽暂存位（目标必为非当前槽，其权威存储即暂存位），不切换当前槽；目标已有档时确认框文案明示覆盖。

## UI 落点

- 顶部状态栏新增「存档」按钮（状态按钮旁），按钮文字由 `render()` 动态显示为「存档·槽N」标明当前槽；
- 点击打开「存档槽」弹窗（复用 `.modal-mask/.modal` 样式）：3 张槽卡（当前槽红框 + 「当前槽」标记），每张显示摘要——第 X 周 · Day N · 排名 · 战绩 胜-负 · 金钱 · 生涯阶段名（空槽显示「空」；当前槽摘要读内存 `S` 保证与界面一致）；
- 非当前槽卡有「切换到此槽」「复制当前进度到此槽」两个按钮，**均先弹既有确认框**（切换框展示当前/目标两槽摘要并说明当前进度会自动存回本槽；复制到有档槽时明示覆盖），符合项目「消耗/覆盖类操作先确认」规范；
- 「重新开始」确认弹窗文案已改：明示只清**当前槽**（打开时动态填槽号）、其他槽不受影响；其执行端同步清理当前槽暂存位（防御性），meta 与其他槽不动。

## 测试档兼容结论

- key 层面：`BACKUP_KEY` 与 meta/槽 key 前缀不同，无冲突。
- 流程层面：开测试档仍是「SAVE_KEY 原文 → BACKUP_KEY」快照，meta 在整个测试期间不变；恢复仍是「BACKUP_KEY → SAVE_KEY + 删备份 + load()」，因此**恢复必然回到开启测试档前所在的那个槽**，无需改动既有代码即可成立——前提是测试期间不切槽。
- 为守住该前提：测试期间（`S.testMode` 为真或存在主存档备份时，`slotsLocked()`）切槽/复制被守卫拒绝，存档面板显示提示且按钮禁用，需先「恢复主存档」。
- 冒烟已覆盖此组合（见下）：在槽 2 开测试档 → 切槽被锁 → 恢复后回到槽 2 的原进度且当前槽仍为 2、备份已清空。

## 测试

`tests/smoke.mjs` 新增 7 项断言（工程版 + dist 版各一份），基线由 80/80 升至 **94/94 全过**：
1. 老存档自动成为槽 1（无 meta 时 currentSlot=1，胜场/排名无损）；
2. 在槽 1 推进后切到空槽 2 得新档（Day 1/0 胜/¥100/meta 落盘）；
3. 槽 2 推进后切回槽 1，进度逐项一致且槽 2 暂存完好；
4. 复制当前进度到槽 3，暂存内容一致；
5. 切到槽 3 内容一致；
6. meta 当前槽在整页重读后保持（槽 3 + 进度一致）；
7. 测试档组合：在槽 2 开测试档、切槽被锁、恢复回到槽 2 原进度。

另以一次性 jsdom 脚本走真实 UI 点击验证（不入冒烟）：顶部按钮显示「存档·槽1」→ 面板 3 卡与当前槽标记/摘要正确 → 点「切换到此槽」弹确认框 → 确认后切到槽 2 新档、面板关闭 → 「重新开始」弹窗槽号与「其他槽不受影响」文案正确，全程无脚本错误。
