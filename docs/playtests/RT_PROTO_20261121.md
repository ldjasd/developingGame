# 实时战斗可玩原型（3D，背后视角，2026-11-21）

> 场景：`godot/scenes/dev/rt_proto.tscn`（脚本 `scripts/dev/rt_proto.gd`）。规则全由 `BattleCore` 判定，画面只订阅事件。
> 角色暂用 VRoid CC0 样例模型（`godot/assets/proto3d/`，需按该目录 README 下载）；主角 / 林小葵的正式模型到位后直接替换。
> 截图：`../research/rt_proto_20261121/`。视频（仓库外）：`D:\gamemake\sfx_preview\rt_proto_match.mp4`（势均一场）、`rt_proto_knockdown.mp4`（击倒 → 起身 → 第二次击倒 KO）。

## 怎么玩
用 Godot 4.7.2 打开 `godot/project.godot`，在文件系统里双击 `scenes/dev/rt_proto.tscn`，按 F6（运行当前场景）。

| 操作 | 键 |
|---|---|
| 走位 | W 前压 / S 后退 / A D 绕圈；双击 = 垫步 |
| 刺拳 / 直拳 / 摆拳 / 上勾 / 击腹 | J / K / U / I / L |
| 格挡 | 按住空格（同时按住 S = 低格挡，专防击腹） |
| 闪避 | Shift + A / D 左右闪，Shift + S 下潜 |
| 切镜头 | C（自动 / 背后锁定 / 第三人称斜后方 / 转播机位） |
| 再来一局 / 退出 | Enter / Esc |

小提示：对手出拳前拳套会**发黄光**（预兆）。直拳和刺拳用左右闪躲，摆拳用下潜躲；躲开后 1 秒内反击伤害 +40%。

## 现在有的
- 3 回合 × 60 秒；回合间暂停 3 秒，有开场铃 / 终场铃。
- 双方 HP（粉）、体力（蓝）、重创（橙）条；回合钟。
- 出拳、格挡（高 / 低）、三向闪避、受击后仰 / 弯腰、重击推镜 + 顿帧、真实音效。
- 「反击！」「N 连击」「闪开了！」「击腹破防！」提示；被打中时屏幕泛红。
- 击倒：单膝跪地 → 读秒数字 → 站起来；KO 时读到 10 → 「K.O.」→ 结果。读秒时站着的一方让到一边，倒地的人始终看得见。

## 擂台走位 + 四种镜头（2026-11-21 用户：「背后视角不容易把移动加进去，第三人称是不是更好」）
- **规则内核加了走位**：两人在擂台平面上有位置；W/S 前压 / 后退，A/D 绕着对手转圈；围绳挡住、不能穿过对手；**超出射程就打空**（直 / 刺 1.30m、击腹 1.10m、摆 1.08m、上勾 0.98m），打空摆拳 / 上勾会给对方反击窗口。AI 按风格保持距离（力量型贴身、速度型拉开）、来回绕圈、被逼到绳边会往场中绕出去，够不着时先压上来再出拳。
- **按键改了**（WASD 要给走位用）：J 刺拳、K 直拳、U 摆拳、I 上勾、L 击腹；空格格挡（+S 低格挡）；Shift + A/D/S 闪避。
- **C 键在四种镜头之间切换**（同一场比赛四机位对比视频：`D:\gamemake\sfx_preview\movement_cameras.mp4`，截图 `../research/rt_proto_20261121/movement_4cams.jpg`）：

| 镜头 | 说明 | 优点 | 缺点 |
|---|---|---|---|
| **自动（默认，Claude 推荐）** | 贴身对打时在背后；拉开距离或绕圈时自动拉到斜后方，靠近又推回来 | 对打时有压迫感、走位时看得清擂台 | 切换中镜头在动，需要实玩确认会不会晕 |
| 背后锁定 | 永远在主角背后、跟着两人连线转 | 压迫感最强，读招最清楚 | 绕圈时整个擂台在转，看不出自己离绳多近 |
| 第三人称斜后方 | 连线后方转 40° 看两人中点 | 两人全身、擂台位置都清楚 | 对手的拳不是冲着你来，压迫感弱 |
| 转播机位 | 擂台边固定机位，只转头 | 最像电视转播、最好看 | 主角在画面里方向一直变，操作方向会乱 |

- **重新标定**：加走位后每场命中从 83 降到 61，HP 池倍率 3.0 → 2.5。600 场：判定 50% / KO 47% / TKO 4%，平均 2.85 回合，势均 54%，+6 属性优势 72%（略低于 75% 验收线；比加走位前的 93% 平缓得多，对生涯难度反而有利，暂时接受，生涯平衡时再看）。

## 距离要真的变化（2026-11-21 用户：「两人之间的距离不应该是不变的，应该有前走后走、左右」）
**原因**：AI 每帧都盯着自己想要的距离，你进它就退、你退它就跟，所以看起来距离锁死。
**改法**（`battle_core.gd`）：
- **步法意图**：AI 每 0.8~2.2 秒重选一次——试探（远处绕圈，太近才退）/ 压上（冲到拳距）/ 站住（不动，你可以贴上去）/ 后撤（受伤、没体力时多）。力量型多压、速度型多试探、防反型多站住；对手快不行时会压上来终结。出完拳 40% 会退出来（打了就走）。
- **出拳带着身体往前送**（直拳最多）：玩家和 AI 都有，打空率从每场 38 次降到 3 次。
- **垫步**：双击 W/A/S/D 快速前冲 / 后撤 / 侧移（0.15 秒约 0.5 米，耗 6 体力）；AI 远距离压上时、被贴身想退时也会用。
- **回合开始两人分开 2.2 米**，先走近再打。
- **脚步动画**：按移动方向左右脚交替迈步、抬脚，移动时脚不再在地上滑。
- 修了一个规则偏差：同一帧两拳同时到时总是玩家方先结算（会打断对方），改成每帧随机先后。
- **重新标定**：HP 池 2.5 → 1.9。600 场：判定 44% / KO 51% / TKO 5%，平均 2.77 回合，每场击倒 2.0，势均 45%，+6 属性优势 83%，平均距离约 1.1 米且一直在变。验收线全过。
- 录像：`D:\gamemake\sfx_preview\footwork_rhythm.mp4`；截图 `../research/rt_proto_20261121/footwork_sheet.jpg`。

## 观众随局势变化（2026-11-21 用户：「KO 时的欢呼是起立鼓掌那种，不是随局势逐渐紧张的体育赛场那种」）
- 新素材（CC0，原始文件在仓库外 `D:\gamemake\third_party_dl\freesound_crowd2\`）：Madison Square Garden 场馆实录 27 分钟、拳击现场观众呼喊、观众反应合集（oohs / ahh）。`godot/tools/make_crowd_layers.py analyze` 按每秒响度 + 频谱平坦度（排除风琴 / 喇叭 / 口哨这类音调声）挑段，导出到 `godot/assets/audio/crowd_dyn/`。频谱自查时发现一段爆发里有持续高频横线（疑似口哨 / 场馆喇叭），已换掉。
- 混音（`rt_proto.gd` `_update_crowd`）：一个「紧张度」0~1 控制两条循环底层（低声嘈杂 ↔ 激动呼喊，等功率交叉）和总音量（−15 → −5 dB）。
  | 局势 | 观众 |
  |---|---|
  | 平时 | 低声嘈杂 |
  | 有人 HP < 40% / 第 3 回合最后 20 秒 | 持续升温 |
  | 重拳、反击、3 连击以上 | 瞬间抬升（重拳带一声「噢！」），再慢慢回落 |
  | 击倒读秒 | 越数越响 |
  | 站起来 | 一阵欢呼 |
  | KO | 爆发；「K.O.」弹出时再一次 |
  | 回合间 | 回到低声嘈杂 |
- 试听：`D:\gamemake\sfx_preview\crowd_dynamic_audition.wav`（嘈杂 → 升温 → 5 声「噢」→ 2 段爆发）；整场：`crowd_dynamic_match.mp4`（2 次击倒 + KO）。

### 第二版：去掉掌声，照真实拳击现场改（同日，用户：「不需要鼓掌，找真实的拳击比赛看一下，KO 前后的观众反应」）
- **参照实测**：在内置浏览器里播放真实拳击 KO 的看台录像（Pacquiao–Hatton KO 观众反应、Pacquiao–Thurman 第 1 回合击倒观众反应），用浏览器自带的音频分析每 0.25~0.5 秒测响度、高频（2~8kHz）占比、「掌声式瞬态」（高频能量 25ms 内跳升 3 倍）。只分析、不下载、不进游戏。结论：
  1. **全程没有掌声**（瞬态 0），全是人声吼叫，高频占比 0.05~0.10；
  2. **KO 后持续高位吼叫 20 秒以上**，不是喊一声就落下；
  3. 手机录像自动增益把响度压平了，KO 前的升温幅度测不准，按拳击常识设计（有人被打得撑不住时全场越来越响）。
- **同样的指标量第一版素材**：激动层、5 声「噢」都有掌声（瞬态 0.7~2.1 次 / 0.5 秒、高频占比 0.13~0.18）——「噢」取自的观众反应合集里有鼓掌和笑声；KO 爆发只有 5 秒、落得太快，像演出结束的掌声。
- **改法**：`make_crowd_layers.py` 加掌声检测（`clap_profile` / `scan_clean`），所有素材只从无掌声窗口取，导出后 `check()` 逐个复检（全部 OK）；新增第三层「持续吼叫」循环；「噢」改为从无掌声吼叫里切片塑形；混音改三层（嘈杂 → 激动 → 持续吼叫），被打的一方 HP 越低每拳抬升越多（KO 前升温），读秒越数越响，**KO 后 22 秒保持最高层**，之后变成激动议论。
- 复测（整场录像音轨）：KO 后 25 秒高频占比 0.07、16 秒保持在 −22dB 以上。

## KO 冲击感（2026-11-21 用户反馈「KO 没有冲击感」后加）
只改呈现，规则不动：
| 阶段 | KO（读到 10） | 普通击倒 |
|---|---|---|
| 那一拳 | 顿帧 0.24 秒 + 白闪 + 爆点（星爆 + 扩散环 + 飞溅）+ 两层重击声 + 观众爆发 | 顿帧 0.14 秒 + 小白闪 + 爆点 |
| 慢动作 | 0.25 倍 × 0.95 秒，镜头同时推近 | 0.5 倍 × 0.35 秒 |
| 倒下 | 头猛地后仰、整个人往后弹，然后仰面倒地（落地闷响 + 小震 3px 量级） | 先后仰，再膝盖一软跪下 |
| 镜头 | 切到倒地者斜前方，像转播一样慢慢绕开站立方 | 站立方让到一边 |
| 读秒 | 加快到 0.55 秒一个，读到 10 →「K.O.」放大弹入 + 重击声 + 观众 | 每秒一个，带弹跳动画 |

## 已知问题 / 下一步
1. **需要你上手打一局**，按 `process/TESTING.md` 第 4 层的问卷打分：看得出对手出什么拳吗？按键有没有延迟？闪避反击爽不爽？
2. 样例模型穿裙装、和我们的角色不像 → 等 VRoid 模型（`tech/VROID_GUIDE.md`）。
3. 拳套是球体占位 → 要做拳套模型。
4. 头发不摆动（未启用原生物理库）。
5. 没有回合间指导面板、赛前 VS、必杀；没有接进生涯（还是独立场景）。
6. 动作是程序生成，略僵硬；正式版考虑加动作捕捉素材（Mixamo）或手调关键帧。
