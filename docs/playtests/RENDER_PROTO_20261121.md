# 战斗渲染试点：2D 立绘 vs 3D 模型（背后视角，2026-11-21）

> 目的：决定战斗角色用 2D 还是 3D（`../DECISIONS.md` 待定 #2，`../design/battle.md` §10）。
> 工程：`godot/scenes/dev/cam_proto.tscn`，同一段 11 秒攻防，`--model=2d` / `--model=3d` 切换，`--view=2` 只看背后视角。
> 截图：`../research/render_proto_20261121/`。视频（仓库外）：`D:\gamemake\sfx_preview\render_2d_vs_3d.mp4`（左右对比）、`render_2d_vs_3d_halfspeed.mp4`（半速）、`camera_compare_3d.mp4`（3D 四机位）。

## 试点里各用了什么

| | 2D | 3D |
|---|---|---|
| 对手 | 林小葵现有的透明底正面立绘（1 张） | VRoid 官方 CC0 样例 AvatarSample_E（棕色短发、绿衣，最像林小葵） |
| 主角 | 几何体人偶虚化（没有背面图） | AvatarSample_G（粉金色马尾，最像主角），身体虚化、拳套不透明 |
| 动作 | 整张图位移 / 倾斜 / 缩放 | 和几何体人偶同一套动作逻辑，用两段 IK 写进人形骨骼（出拳弧线、躯干转动、下潜、闪避、受击后仰、屈膝都有） |
| 着色 | 原图 | MToon 卡通着色（VRM 自带） |
| 工具 | — | Godot VRM 导入插件 v2.6.1（MIT，AzPepoze 维护的 V-Sekai 分支） |

## 评估表（Claude 打分，1~5；你看完视频也打一份）

| 项 | 2D（单张立绘） | 3D（样例模型） | 说明 |
|---|---|---|---|
| 像不像我们的角色 | **5** | 2 | 2D 就是我们的原画；3D 用的是现成样例，脸、服装都不是我们的人。换成按立绘捏的 VRoid 模型后预计 3~4 |
| 打击感 | 2 | **4** | 2D 的「出拳」只是整张图往前冲，手不动；3D 拳头真的打出去、头真的被打后仰 |
| 动作流畅 | 2 | **4** | 3D 有轻微僵硬（程序动作、没用动作捕捉），但连贯 |
| 加一个新角色 | 1 张立绘就能上场，但只能「滑」；要真能打，需要约 12 张一致的正面姿势 + 主角 12 张背面 | 1 个模型（VRoid 里捏约 1~2 小时）+ 导入几分钟；动作全员共用 | |
| 换装 / 换拳套 | 每套服装要重画所有姿势 | 换材质颜色或换网格，几分钟 | |
| 崩坏风险 | 补画姿势后：姿势之间脸 / 比例不一致（项目之前放弃抠帧就是这个原因） | 穿模（手臂穿过裙子）、模型风格和立绘不完全一样 | |

## 结论与建议

**建议走 3D。** 理由：
1. **能真打**：实时战斗要的是出拳、闪避、受击的真实肢体动作。2D 单张立绘做不到；补画姿势要 50 人 × 12 张 + 主角背面，而且一致性正是项目以前栽过的坑。
2. **成本按「人」算而不是按「姿势」算**：3D 一个角色一个模型，动作、预兆、受击全员共用（和 Love Upper 11 人共用 358 段动作同一个思路）。
3. **装备 / 服装可见**几乎免费，`design/equipment.md` 的「外观是重点」能落地。
4. 2D 立绘不浪费：中枢、剧情、选人、商店继续用 2D，3D 只在擂台上。

**3D 的代价和要解决的事**
- **角色模型要按我们的立绘重做**：主角、林小葵先做两个（用 VRoid Studio 捏：发型、发色、眼睛、运动背心 + 短裤 / 短裙、拳击鞋）。VRoid 是图形界面软件，需要有人操作——你来，或者我写一份逐步指引。
- **服装**：样例模型穿的是裙装 / 礼服，正式模型要换成运动服，穿模会少很多。
- **头发摆动**：插件的头发物理靠一个原生库（.dll），这次为了不运行下载的二进制文件没装，所以头发不动。正式要用的话：从插件源码自己编译，或审过来源后启用。
- **动作质量**：现在是程序动作。正式版可以加 Mixamo 免费动作（需要你登录 Adobe 账号下载）或在 Blender 里手调关键帧，节拍按 `design/battle.md` §3.2。
- **镜头**：背后视角在 3D 下调到「镜头高 2.7 米、在主角后 1.75 米、视野 40°」时，主角的头落在对手脸下方，对手的脸始终看得清（中间几版主角头会压住对手脸）。
