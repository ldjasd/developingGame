# 拳击养成游戏长期计划

> 制定：2026-10-24 | 原则：系统先于美术，每个阶段结束都有可玩版本，按兴趣和空闲推进，无硬性 deadline
>
> **迭代方式（2026-10-24 定）**：两轮走——第一轮按 Phase 1→5 顺序把整套系统先跑通；每个 Phase 结尾总结给用户，用户给建议后再继续；2~3 轮后助手已摸清用户偏好，转自主 loop；第一轮完成后做一次整体评估，总结问题清单；第二轮按同样顺序逐项回炉更新迭代；完成度足够后进 Phase 6+。
>
> **第二轮回炉（2026-10-24）已完成，完整过程记录见 ROUND2.md，待用户复核后再改。**

- **第二轮回炉（2026-10-24 已完成，详见 ROUND2.md）**——按第一轮问题清单修复 P0/P1/P2：战斗数值重调（重创值 刺6/直12/上勾18/摆18/击腹12、衰减 6/秒、对手缩放封顶＋前两周缓冲）、粉丝改为影响力 5 档、商店确认框、训练预览、比赛日睡觉警告、键位弹窗取消、16 项小瑕疵；实测第 1 周 200 场 R2 67.5%、R3/点数 38.5%、胜率 52.5%，第 10 周胜率 46.0%；单次 KO 阈值纠回用户拍板的 30%（击倒带 25%~30%），待用户复核后再改

## Phase 4：战斗深化（2026-10-24 已落地：组合拳、反击窗口、破防克制、AI 三风格、击倒读秒、回合间休整）

目标：让战斗从"贴身出拳循环"变成有决策的攻防。

- 组合拳：连续命中连击计数＋伤害加成
- 反击窗口：闪避成功后 1 秒内出拳伤害加成
- 破防克制：高位格挡防不住击腹，击腹破防接直拳成标准连招
- AI 风格：力量型 / 速度型 / 防守反击型，对手打法各不同
- 击倒/读秒：被重击倒地→读秒→可起身再战，不只有 KO 一种结局
- 回合间：体力小幅恢复＋伤势显示
- 完成标准：手动打一场能明显感觉到"打对了"和"打错了"的区别

## Phase 5：装备深层系统

- 双层结构落地：版型（守护/斗牛/经典）× 材质（外皮＋内衬）× 盎司（8~16oz）× 固定方式（系带/魔术贴）
- 制作系统：拆解淘汰装备→皮料/内衬材料→按配方打造新装备
- 拳套图鉴成就：集齐奖励
- 完成标准：装备不再是几件固定商品，而是一套可搭配、可打造的系统

## Phase 6：捏人 / 换装 / 换发型（2026-10-24 已落地，源文件就绪，待父代理走构建 → 审计 → 提交流程发布；完整过程记录见 PHASE6.md）

- 捏人系统：脸型、体型等基础选项——已落地：脸型 3 项（默认/圆润/瓜子）、体型 3 档（娇小 0.92 / 标准 1.0 / 高挑 1.08 纵向缩放，恒叠加于立绘之上）
- 换发型：9 种发型（高马尾、公主切、大波浪、半扎发、超短发、麻花辫、黑长直、丸子头、水波纹）立绘变体，状态界面切换——已落地：高马尾复用 v8 立绘，其余 8 张新图存于 artifact 内 `assets/portrait/`
- 服装换装：战袍/训练服外观切换——已落地：登场战袍、训练服 2 张新图，另加默认项共 3 项
- 显示规则：立绘图片由最近一次切换的维度决定（发型/脸型/服装取最后一次切换的），体型缩放恒叠加；9×3×3 全组合需 81 张图，本期用 13 张立绘图片（v8＋12 张新图）代表变体，属实记录不夸大
- 存档与兼容：四项选择及最后切换维度全部存档、读档恢复；老存档缺外观字段时回落 v8 默认外观
- 完成标准：主角外观可自定义，且不破坏现有立绘风格——已通过 18 项逐项点选、存档重读、老存档兼容、战斗/装备/排名/影响力冒烟验证；未做项：真机手机布局目视（无头环境仅静态 CSS 检查，见 PHASE6.md）

## Phase 7：剧情 / 恋爱线（2026-10-25 已落地，详见 PHASE7.md）

- 序章：街机拳机→被发掘→进拳馆（参考《マグナムリリィ》素人开局）——已落地：测力机点按蓄力＋梢姐搭话＋选项式试训，仅新存档触发、可跳过，老存档自动跳过
- 分阶段剧情事件：随生涯阶段解锁——已落地：阶段主线 6＋关键节点 7，结算后排队弹出、不耗 AP
- 恋爱线（可选）：队友/对手等角色好感事件——已落地：梢姐/真纪/沈墨凛/林小葵 4 人好感（状态页关系区），每人 30/60/90 三段专属事件，只到心动暗示、无惩罚
- 完成标准：生涯有了故事线，但不强制、不干扰核心循环——达成；事件共 28 段，冒烟 59 项全过
- 衔接事项：宿敌 18% 概率登场为临时方案，角色池系统接入后改由池内真人匹配（见 ROSTER.md 实现备注）

## Phase 7.5：代码工程化（2026-10-25 用户新指示，v1 已完成）

- v1 成果（2026-10-25）：独立工程位于 `web/`——index.html 页面壳＋css/main.css＋js/data.js（纯数据）＋js/story.js（剧情）＋js/game.js（主逻辑逐字搬运），assets 相对路径不变、工程根目录直接可跑；scripts/build-single.mjs 可打包回单文件 dist/；tests/smoke.mjs 同组 21 项断言在工程版/dist 版/原 artifact 版三方 63/63 一致，逐行多重集比对差 0
- v2 路线（README 已写）：game.js 再细拆 audio/story-engine/battle/ui，逐段搬运、每段跑全套冒烟

- 背景：用户明确要求后续把代码从单个 HTML 里搬出来，不再长期维护单文件 HTML；角色池系统是现有 HTML 原型的最后一项大功能接入
- 目标：把已验证的玩法源码拆成独立工程并入仓库——数据（角色池/装备/剧情）、核心逻辑（战斗/养成/排名）、UI、存档迁移、资源各自成文件，带可重复的冒烟/数值复测脚本
- 衔接：可玩版本由源码工程构建生成，安卓仍可试玩；存档格式保持兼容或提供迁移；设计与数值以当前验证版为准，不借搬迁改玩法
- 完成标准：仓库里有一套能独立打开/构建/测试的源码工程，单文件 HTML 只作为构建产物，不再是唯一源码

## Phase 8：Godot 正式版迁移

- 完成标准：Godot 版玩法与原型一致，表现升级
