# 发布路线图：从现在到 1.0

> 制定：2026-11-21。依据：`AUDIT_20261121.md`。旧路线图（网页版 Phase 1~9）已归档到 `archive/web-prototype/ROADMAP_web.md`。
> 用法：一次只做一个阶段。每个阶段有**目标、任务、要写 / 更新的文档、出口标准**。出口标准全部达成才进下一阶段。阶段内的每一项任务按 `process/WORKFLOW.md` 的流程走。

## 总览

| 阶段 | 名字 | 一句话 | 预估 |
|---|---|---|---|
| P0 | 方向定稿 | 把会推翻后面工作的大问题先定下来 | 1~2 周 |
| P1 | 垂直切片 | 做出「一场完整的、接近最终品质的实时比赛 + 两周生涯」 | 3~5 周 |
| P2 | Alpha（功能齐） | 所有系统都在、能从开局玩到结局（美术可以是占位） | 6~10 周 |
| P3 | Beta（内容齐） | 所有美术 / 音频 / 文案到位，平衡达标，外部试玩 | 6~10 周 |
| P4 | 发布候选 → 1.0 | 打包、署名、发布页、修 bug | 2~3 周 |

> 名词：**垂直切片**＝只做一小块，但这一小块的品质接近成品，用来证明「这个游戏最终会是这个样子、而且好玩」。**Alpha**＝功能都有了。**Beta**＝内容都有了，只剩打磨和修 bug。

## P0 方向定稿（现在）

**目标**：把 `AUDIT` §9 的 6 个问题定下来，尤其是战斗视角和渲染路线。

**任务**
1. 你拍板：战斗视角、生涯终点、装备收缩、发布渠道、命名方式（`DECISIONS.md` 待定区）。
2. **战斗渲染试点**（我做，muse 出 2D 素材）：按 `design/battle.md` §10，2D 和 3D 各做「主角 vs 林小葵 1 回合」，填评估表。
   - 3D：装 VRoid Studio（需要你或我在图形界面操作）、Godot VRM 插件、下载 Mixamo 拳击动作（需要 Adobe 账号，你登录）。
   - 2D：muse 出对手正面 12 张、主角背面 12 张。
3. 实时战斗内核原型（无画面，只跑规则）：`BattleCore` 60Hz 步进 + AI 大脑，机器人能打完整场。
4. 定版 `VISION.md`。

**要写 / 更新的文档**：`VISION.md`、`DECISIONS.md`、`design/battle.md`（视角和路线结论）、`design/characters_art.md`（生产流程）、试点报告 `playtests/`。

**出口标准**
- [ ] 待定区 6 项全部有结论（已定：视角＝背后、渲染＝3D；剩生涯终点、装备、发布渠道、命名）；
- [x] 试点已做、路线已定（3D，2026-11-21）；
- [x] `BattleCore` 无画面跑 1000 场不报错，终结分布达 `battle.md` §11 数据线（2026-11-21，`playtests/RT_CORE_20261121.md`）；
- [ ] 主角 + 林小葵 VRoid 模型（`tech/VROID_GUIDE.md`）。

## P1 垂直切片

**目标**：一场让你觉得「对，就是这个」的实时比赛，加上接在它前后的两周生涯。

**任务**
1. 战斗：手动模式完整可打（出拳 / 格挡 / 三向闪避 / 反击 / 读招 / 必杀 / 击倒读秒 / 回合间指导）。
2. 战斗表现：主角 + 林小葵按选定路线做到最终品质（所有动作、受击 5 档、倒地起身）。
3. 打击感重新对时：顿帧、特效、音效按新动作节拍对齐。
4. 战斗 HUD、赛前 VS、赛后结算按 `design/ui_ux.md` 做出正式样式。
5. 教学赛：序章最后一场引导玩家学会格挡、闪避、反击。
6. 工程：`main.gd` 拆成独立场景；全局 Theme 资源；`InputMap` + 手柄。
7. 设置界面（音量 / 窗口 / 键位）和暂停菜单。

**文档**：`design/battle.md` 定稿、`design/ui_ux.md` 定稿、`tech/ARCHITECTURE.md` 更新、切片试玩报告。

**出口标准**
- [ ] 真人试玩（你 + 至少 1 位没玩过的人）手感问卷每项 ≥ 4/5（`battle.md` §11）；
- [ ] 机器人数据线达标；
- [ ] 冒烟测试全过；60 fps 稳定（1080p）。

## P2 Alpha（功能齐）

**目标**：从新游戏一路玩到结局，所有系统都在。

**任务**
1. 生涯：终点、世界挑战赛、3 种结局、退役压力、难度梯度、宿敌触发（`design/career.md` §2）。
2. 装备收缩 + 服装收集 + 存档迁移（`design/equipment.md`）。
3. 训练小游戏 3 种。
4. 经济重调（第 20 周存款 ≤ ¥5,000）。
5. 全部 50 名对手接入新战斗表现（可以先用占位：3D 路线用同一底模换色，2D 路线用少量姿势）。
6. 自动观看模式 + 模拟跳过模式接新内核，模拟拟合（残差 ≤ ±15pp）。
7. 剩余界面：存读档、档案（状态 / 背包 / 图鉴 / 成就 / 排名）、致谢、结局。
8. 剧情：结局、世界篇、宿敌线的文案初稿。

**文档**：`design/career.md`、`design/equipment.md`、`design/story.md` 定稿；平衡报告。

**出口标准**
- [ ] 机器人 normal 策略能打到结局，周数在 40~60；
- [ ] `career.md` §3 平衡目标全部达标；
- [ ] 一次真人完整通关（你），没有卡死 / 存档坏 / 无法继续的 bug；
- [ ] 没有「功能缺失」类待办（只剩内容和打磨）。

---

## P3 Beta（内容齐）

**目标**：所有占位换成正式内容，外部试玩。

**任务**
1. 美术：50 名对手正式战斗表现、事件 CG、结局 CG、中枢换装、擂台。
2. 音频：BGM 来源确认或替换、补齐 `design/audio.md` §3 音效、结局 / 胜负曲。
3. 文案：52 人命名、全部文案终审。
4. 分辨率 / 手柄 / 键位全覆盖测试。
5. 外部试玩 3~5 人（朋友），用 `process/TESTING.md` 的反馈表收集，按严重度修。
6. 性能：读档 / 进比赛时间 < 3 秒。

**文档**：外部试玩报告、`process/ASSET_REQUESTS.md` 全部关闭、`CREDITS` 完整。

**出口标准**
- [ ] 游戏里没有任何占位图 / 占位名 / 未知来源素材；
- [ ] 外部试玩者平均「想继续玩」≥ 4/5；
- [ ] 严重 bug（崩溃、存档损坏、卡关）为 0。

## P4 发布候选 → 1.0

**任务**：按 `process/RELEASE_CHECKLIST.md` 逐项完成——版本号、图标、Windows 导出、安装包 / zip、致谢页、许可证文件、itch.io 页面（截图、介绍、标签）、发布后反馈渠道。

**出口标准**：清单全勾；在一台干净的 Windows 电脑上下载 → 安装 → 通关一次无问题。
